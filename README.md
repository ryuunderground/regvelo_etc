# DrugCLIP으로 BPA/비스페놀류 내분비교란물질 스크리닝

DrugCLIP(단백질 포켓-화합물 대조학습 기반 초고속 가상 스크리닝 모델, Science 2026)을 로컬(CPU, Apple Silicon)에서 돌려서, 비스페놀A(BPA)와 그 유사체들이 어떤 핵수용체에 얼마나 잘 붙는지 스크리닝하고, 실제 문헌/결정구조와 대조 검증한 기록입니다. 아래는 처음부터 지금까지 실제로 한 작업을 순서대로 정리한 것입니다.

---

## 1단계 — DrugCLIP 환경 구축 (CPU, uv)

**논문**: `papers/drugclip.pdf` — 포켓 인코더와 분자 인코더를 대조학습으로 정렬해서, 결합 예측을 "회귀"가 아니라 "임베딩 유사도 검색" 문제로 푸는 모델. 도킹보다 최대 1000만 배 빠름.

- `github.com/THU-ATOM/DrugCLIP` (NeurIPS 2023 공식 코드)를 `DrugCLIP/`에 클론
- `uv`로 Python 3.10 가상환경(`.venv/`) 생성, `requirements.txt`로 의존성 설치 (torch 2.0.1, rdkit==2022.9.5, biopandas 등)
- `unicore`(모델 프레임워크, DrugCLIP과 같은 랩 제작)를 소스에서 빌드 — `pkg_resources`/`setuptools` 버전 문제 등 몇 가지 빌드 이슈 해결
- **CPU 전용 버그 2개 발견 및 패치** (원본 코드는 GPU 전제로 작성됨):
  - `unicore.utils.move_to_cuda`가 CPU에서 무조건 `torch.cuda.current_device()`를 호출해서 크래시 → CPU일 때 no-op으로 패치
  - `unimol/models/drugclip.py`의 `logit_scale` 파라미터가 `device="cuda"`로 하드코딩되어 있어 모델 생성 자체가 CPU에서 실패 → 제거
  - `retrieval.py`가 검색 결과를 계산만 하고 출력/저장을 안 하는 버그도 발견해서 고침 (원본 저장소 자체의 버그)
- 모델 가중치(`checkpoint_best.pt`, 1.1GB)와 예제 데이터(`mols.lmdb` 294만 화합물, `pocket.lmdb`)를 Google Drive에서 다운로드 — 중간에 네트워크가 끊겨서 재다운로드하기도 함
- 300개 화합물 서브셋으로 **end-to-end 스모크 테스트 성공**

## 2단계 — 역방향 검색(target fishing) 추가

기존 DrugCLIP은 "포켓 하나 고정 → 화합물 랭킹"만 지원. 반대 방향("화합물 하나 고정 → 어떤 리셉터에 잘 붙는지 랭킹")은 없어서 직접 추가:

- `unimol/tasks/drugclip.py`에 `encode_pockets_once()` / `retrieve_pockets()` 추가 (기존 `retrieve_mols()`의 미러 버전, 리간드-포켓 역할만 바꿈)
- `unimol/retrieve_receptors.py` 새 CLI 진입점
- 검증: 정방향 1위 화합물의 점수(0.5582)와 역방향 결과가 정확히 일치 — 구현이 맞다는 교차검증

## 3단계 — BPA/비스페놀 패널 구축 (11개 화합물 × 7개 리셉터)

**중요**: 여기서부터는 기존 DrugCLIP 체크포인트를 **그대로 쓰는 조회(zero-shot)** 이지, 재학습이 아닙니다. 화합물 2~3개로 파인튜닝하면 통계적으로 의미가 없다는 게 이 프로젝트 초반에 나온 핵심 결론이라, 계속 이 원칙을 지켰습니다.

- **화합물 11개** (`bpa_panel/compounds.csv`): BPA + BPS, BPF, BPAF, BPB, BPE, BPZ, BPC, BPAP, TBBPA, TCBPA. SMILES는 전부 PubChem API에서 직접 조회해서 검증
  - 주의사항 하나 발견: PubChem이 "Bisphenol C"라고 부르는 화합물(CID 6620)은 독성학 문헌이 실제로 말하는 BPC(다른 구조)와 다른 화합물이었음 — CSV에 명시
- **리셉터 7개** (`bpa_panel/receptors.csv`): ERalpha, ERbeta, ERRgamma, PPARgamma, AR, THRbeta, PR — 문헌상 BPA 타깃으로 보고된 핵수용체들. 전부 **실제 PDB 결정구조**(AlphaFold 아님) 사용, 각각 출처 논문/PDB ID 기재
- `build_pockets.py`: 실제 PDB 다운로드 후 포켓 추출 (참조리간드 6Å 이내 잔기, 원본 저장소의 `write_dude_multi.py` 로직 재사용)
- `build_mols.py`: RDKit으로 11개 화합물의 3D 컨포머 생성
- `score_matrix.py` (신규 CLI): 기존 `retrieve_mols`/`retrieve_pockets`는 top-k만 반환하는데, 7×11처럼 작은 패널은 전체 쌍을 다 보는 게 낫다고 판단해서 **전체 매트릭스**를 반환하는 버전을 추가
- **결과**: BPA가 ERRgamma에서 11개 중 2위(상위 90.9%) — 문헌상 알려진 가장 강한 친화도(Kd=5.5nM)와 일치. ERalpha에서는 중간(상위 63.6%)

## 4단계 — 문헌 검증 (병렬 에이전트 4개)

ERalpha에서 BPA보다 점수가 높게 나온 화합물 4개(BPZ, BPB, BPC, TCBPA)에 대해, 각각 "진짜 문헌에도 그런 근거가 있는지" 에이전트 4개를 병렬로 띄워서 확인 (`bpa_panel/eralpha_literature_check.csv`):

| 화합물 | 결과 |
|---|---|
| BPZ | ✅ 확인됨 (2개 독립 연구, BPA 대비 ~3배 강함) |
| BPB | ✅ 확인됨 (15개 연구 리뷰 + 직접비교) |
| BPC | ⚠️ **검증 불가** — 우리가 스크리닝한 화합물이 문헌이 말하는 "진짜 BPC"와 다른 구조였음 |
| TCBPA | 🟡 문헌 엇갈림 — 모델 예측을 뒷받침 못함 |

## 5단계 — "친구들만 비교한 거 아니냐" 재검증

사용자 지적: 11개 패널이 전부 비스페놀류라서, "BPA가 상위 63.6%"라는 숫자는 **BPA의 사촌들 사이에서의 순위**일 뿐 전체 화학공간에서의 순위가 아님. 실제로 검증:

- DrugCLIP의 실제 화합물 라이브러리(294만 개)에서 2만 개를 랜덤 샘플링 + BPA 추가해서 ERalpha 기준 전체 재랭킹 (`bpa_panel/library_ranking.csv`)
- **결과: BPA가 20,001개 중 3위 (상위 0.01%)**
- 근데 이것도 다시 의심해봄: "혹시 2만 개 샘플에 BPA의 경쟁자(다른 비스페놀류)가 하나도 없어서 그런 거 아니냐?"
- 294만 개 전체를 SMARTS 구조 검색으로 훑어본 결과, **비스페놀류처럼 생긴 화합물이 전체에서 14개뿐** (`bpa_panel/library_composition_check.csv`). 즉 "3위"는 "BPA가 최강"이 아니라 "이 라이브러리엔 BPA의 경쟁자가 거의 없다"는 뜻에 더 가까움 — 정직하게 정정해서 기록

## 6단계 — 포즈 예측 모델 추가 (Uni-Mol Docking V2)

DrugCLIP은 리간드-포켓을 벡터 하나씩으로 압축해서 코사인 유사도만 비교하는 구조라, **애초에 "어떤 모양으로 붙는지"(포즈)를 표현할 방법이 없음** — 파인튜닝으로 해결 안 되는 아키텍처 한계. 그래서 포즈 예측은 별도의 사전학습 모델을 붙이기로 결정:

- **Uni-Mol Docking V2** 선택 (DiffDock 대신) — DrugCLIP과 같은 랩(dptech-corp) 제작, PoseBusters 벤치마크 정확도 더 높음(77.6%), blind docking(결합부위 안 알려줘도 됨)
- `UniMolDockingV2/`에 설치, 체크포인트(487MB) 다운로드
- **패치**: 모델이 내부적으로 conf_size(10)개 후보 포즈 중 최선을 고를 때 쓰는 자체 신뢰도 점수(`prmsd_score`, predicted RMSD)를 계산만 하고 버리길래, 결과 파일/CSV에 남도록 수정
- **버그 발견 및 수정**: ERalpha/PPARgamma/PR 3개 리셉터의 PDB 파일에 참조리간드가 여러 카피 들어있어서, 그냥 다 풀링하면 도킹 박스가 여러 결합부위에 걸쳐 잘못 커지는 문제 → 하나의 인스턴스만 쓰도록 수정
- **36쌍 테스트** (`bpa_panel/docking/`): 리셉터 6개(BPA 잘 붙는 3개 + 안 붙는 3개) × 리간드 6개(비스페놀 3개 + 무관한 랜덤 화합물 3개)
  - 결과: 비스페놀류가 리셉터 상관없이 일관되게 랜덤 화합물보다 자체 신뢰도가 낮음 (평균 12.3 vs 7.8)

## 7단계 — "신뢰도 낮음"의 진짜 원인: 대칭성 버그 발견

사용자 지적: "그 신뢰도가 이미 10개 후보 중 최선을 고른 거면, 더 해봐야 소용없는 거 아니냐?" (맞음, 코드로 확인) + "우리 연구실에서 BPA가 ERalpha에 잘 붙는다고 나왔는데?" → 실제 정답(결정구조)과 직접 비교해보기로 함:

- ERalpha(3UU7)/ERRgamma(2E2R)/PPARgamma(9F7W)는 **실제로 BPA가 결합된 결정구조**라서 정답을 알고 있음
- BPA를 이 3곳에 도킹시켜서, 예측 포즈를 진짜 결정구조상의 BPA 위치와 비교 (`bpa_panel/docking/verify_bpa/`)
- **핵심 발견**: 원자 순서 그대로 비교한 RMSD는 2~3.7Å(그저 그럼)인데, **BPA의 좌우 대칭성을 고려해서 비교(symmetry-aware RMSD)하면 전부 1Å 미만** (0.55~0.76Å — PoseBusters 기준 "좋은 포즈" 안쪽)

| 리셉터 | 단순 RMSD | 대칭 보정 RMSD | 모델 자체 확신도 |
|---|---|---|---|
| ERalpha | 3.71Å | **0.55Å** | 12.6 (나쁨) |
| ERRgamma | 3.37Å | **0.55Å** | 11.8 (나쁨) |
| PPARgamma | 2.05Å | **0.76Å** | 12.2 (나쁨) |

**결론**: 모델이 예측한 포즈는 실제로 거의 정확했는데, 모델 자체 확신도 계산 방식이 BPA처럼 좌우 대칭인 분자(고리 2개가 거의 똑같이 생김)를 "다른 포즈"로 착각해서 확신도를 실제보다 훨씬 나쁘게 평가하고 있었던 것. 6단계에서 본 "DrugCLIP 점수와 도킹 신뢰도가 안 맞는다"는 문제도, 두 모델이 실제로 어긋난 게 아니라 **신뢰도 지표 자체가 대칭 분자에 불리하게 오염되어 있었던** 것으로 정리됨. 연구실에서 확인한 "BPA-ERalpha 잘 붙음"이 DrugCLIP 랭킹 + 실제 결정구조 + 이번 도킹 재현까지 세 겹으로 뒷받침됨.

## 재현 방법 (요약)

1. `uv venv --python 3.10 .venv && source .venv/bin/activate && uv pip install -r requirements.txt`
2. `unicore`를 소스에서 빌드: `uv pip install "git+https://github.com/dptech-corp/Uni-Core.git" --no-build-isolation`
3. `DrugCLIP/checkpoint_best.pt`는 [원본 레포 Google Drive](https://github.com/THU-ATOM/DrugCLIP)에서 받아야 함 (용량 문제로 이 레포엔 커밋 안 함)
4. `bpa_panel/`, `bpa_panel/docking/`의 각 `build_*.py` 스크립트를 순서대로 실행하면 전체 파이프라인 재현 가능

## 8단계 — `score_matrix.csv` 포켓 풀링 버그 수정 (`build_pockets.py`)

DESIGN.md 작업 중 BPA를 positive/hard-negative로 분류하다가, **PPARγ가 실제 결정구조(9F7W)까지 있는데도 DrugCLIP 점수가 0.0148(거의 0)로 나오는 게 이상해서** 원인을 확인함.

- 원인: 7단계에서 도킹 쪽(`build_docking_inputs.py`)만 고치고 방치했던 "리간드 여러 카피 풀링" 버그가 `build_pockets.py`(스크리닝 점수용 포켓 추출)에는 그대로 남아있었음. 9F7W는 참조리간드(BPA) 카피가 2개라, 풀링하면 두 결합부위가 합쳐진 700원자짜리 뒤죽박죽 포켓이 만들어짐.
- 같은 방식(첫 번째 인스턴스만 사용)으로 수정 후 재추출: PPARγ 포켓 700→422원자, ERalpha 380→186원자, PR 474→240원자 (ERbeta/ERRgamma/AR/THRbeta는 원래 카피가 1개라 변화 없음 — 이 4개 리셉터의 BPA 점수가 수정 전후로 정확히 동일하다는 게 그 자체로 좋은 sanity check가 됨)
- **결과**: PPARγ BPA 점수 0.0148 → **0.5381**로 급등. "모델이 진짜 결합을 놓친 것"이 아니라 **우리 쪽 포켓 추출 버그가 원인**이었음이 확인됨. ERalpha(0.5711→0.8440), PR(0.3497→0.5523)도 크게 변함.
- ERalpha 순위도 바뀜: TCBPA가 4위(BPA보다 위)에서 8위(BPA보다 아래)로 떨어져서, "BPA보다 순위 높은 화합물"은 더 이상 4개가 아니라 3개(BPC, BPB, BPZ)임. 4단계 문헌 검증 결과(`eralpha_literature_check.csv`)는 이 3개에 대해서는 그대로 유효, TCBPA 항목은 "더 이상 BPA를 안 앞선다"는 내용으로 갱신함.
- **AR(0.5887, 변화 없음)이 여전히 ERalpha(0.8440)보다 낮아졌으므로**, "AR이 ERalpha보다 높게 나온다"는 이전 false-positive 관찰은 이번 수정으로 사라짐 — 재확인 필요 (DESIGN.md 갱신 예정)

## 9단계 — 파인튜닝 loss가 진짜 active를 negative로 채점하던 문제

8단계까지는 "점수가 이상하다"를 입력(포켓) 쪽에서 찾았는데, 이번엔 학습 loss 자체를 뜯어봄.

DrugCLIP의 `in_batch_softmax`는 배치 하나에 (리셉터, 화합물) 쌍 8개를 넣고 "이 리셉터의 진짜 짝은 몇 번?"이라는 8지선다를 푸는 구조다. 정답은 자기 짝, **나머지 7개는 전부 오답 처리**된다.

`models/drugclip.py`에 이 오답 처리를 걸러내는 마스크가 원래 있었는데, 거르는 게 두 가지뿐이었다:

- 배치 안에 **같은 포켓**이 두 번 → 제외 ✅
- 배치 안에 **같은 SMILES**가 두 번 → 제외 ✅
- **다른 리셉터인데 그 화합물이 사실 거기에도 붙는 경우** → 못 거름 ❌

핵수용체는 화합물 하나가 여러 곳에 붙는 게 흔하다. 학습 화합물 1,396개 중 **442개가 2개 이상 리셉터에 active**(2개 338, 3개 85, 4개 19). 실측 결과:

> **loss가 실제로 negative로 쓰는 칸의 28.7%가 확인된 active였다.**

**수정** (`3dbc60e`): LMDB 엔트리마다 그 화합물이 붙는 리셉터 전체 목록(`"actives": "ERalpha|PR"`)을 저장하고, 마스크를 "같은 포켓"에서 "그 포켓의 확인된 active"로 확장. `pocket_list[i] ∈ actives[i]`가 항상 참이라 기존 same-pocket 마스킹을 그대로 포함하고, `actives` 필드가 없는 옛 LMDB는 포켓 이름으로 폴백해서 기존 동작이 보존된다. numpy 3중 블록이 리스트 컴프리헨션 하나로 줄어 코드는 오히려 짧아짐. 자체 검사는 `test_actives_mask.py`.

**결과: 고친 건 맞지만 이게 주범이 아니었다.** paired bootstrap(2000 resample) 결과 **리셉터별로 유의하게 좋아진 게 하나도 없다**:

```
leak-free, v2 - v1 AUROC, 95% CI
  ERalpha    -0.015  [-0.051, +0.022]
  AR         -0.019  [-0.049, +0.010]
  PPARgamma  +0.034  [-0.020, +0.104]
  PR         -0.017  [-0.087, +0.038]
  POOLED     +0.014  [+0.000, +0.027]
```

⚠️ **학습 로그의 `valid_bedroc` 0.597 → 0.745, `valid_acc` 0.612 → 0.754를 개선으로 읽으면 안 된다.** 마스킹이 객관식 보기를 29% 줄여서 문제가 쉬워진 것이다. 같은 이유로 학습 loss도 5.54 → 4.35로 내려갔다. v1과 비교 가능한 숫자가 아니다.

그래도 수정은 유지한다. 실측된 라벨 오염이고, 리셉터를 늘리면 화합물당 active 수가 늘어 이 비율이 더 커진다.

## 10단계 — 컨포머 앙상블 (기여분 0.0001)

`AffinityMolDataset`이 컨포머 5개 중 하나를 무작위로 뽑는 대신, 전부 채점해서 pooling하면 나아지는지 확인 (`expand_conformers.py`).

```
                    AUROC     BEDROC
  v2                0.6350    0.3756
  v2 + conf0        0.6396    0.3856   <- 앙상블 없는 대조군
  v2 + conf max     0.6492    0.3857
  v2 + conf mean    0.6364    0.3793
```

conf0(무작위로 안 뽑고 0번을 고정으로 쓰는 대조군)이 이미 0.3856이고 max가 0.3857이다. **앙상블의 기여분은 0.0001.** BEDROC 개선분 전체가 "컨포머 주사위를 다시 안 굴린 것"이었다.

`conformer_spread.py`가 천장이 낮은 이유를 설명한다: 인코더가 컨포머에 눈먼 건 아니고(한 화합물의 모양들이 퍼지는 거리가 서로 다른 화합물끼리의 1/3, 0.06 vs 0.18), 포켓들이 최선 모양에 대해 의견이 갈리기도 한다(일치율 0.500 vs 우연 0.327). 다만 랭킹 상위를 재배치할 만큼 크지 않고, 1,551개 중 562개는 컨포머가 하나뿐이라 pooling이 아예 no-op이다.

conf0을 하드코딩하지는 않았다 — RDKit은 컨포머를 에너지가 아니라 embedding 순서로 내보내므로, 한 패널에서 고정 인덱스가 무작위 인덱스를 이긴 건 규칙이 아니라 운이다. mean pooling이 순서에 의존하지 않고 같은 분산을 제거한다.

## 11단계 — pooled AUROC가 부풀려져 있었다

`auroc_before_after.csv`가 보고하던 **0.5541 → 0.6181**은 재현된다. 문제는 그게 **pooled**라는 것. 리셉터별로 쪼개면:

| 리셉터 | pretrained | v1 | v2 | n (leak-free) |
|---|---|---|---|---|
| ERα | 0.390 | 0.424 | **0.409** | 43+/54− |
| AR | 0.595 | 0.648 | **0.629** | 80+/61− |
| PPARγ | 0.605 | 0.602 | **0.636** | 16+/41− |
| PR | 0.574 | 0.651 | **0.634** | 90+/22− |
| THRβ | 0.692 | 0.692 | **0.673** | 4+/117− ← 무의미 |
| **pooled** | 0.5309 | 0.5991 | **0.6126** | 233+/295− |

pooled가 개별 리셉터 대부분보다 높은 건 Simpson 효과다. THRβ는 negative가 1,143개인데 평균 점수가 제일 낮아서, "ERα positive vs THRβ negative" 같은 **교차 리셉터 비교**(전체 쌍의 ~72%)가 공짜 점수를 준다. 실제 스크리닝은 리셉터 하나 고정하고 화합물을 랭킹하는 것이므로, 정직한 숫자는 **리셉터별 0.41~0.64**다.

`eval_auroc.py` 신규: 리셉터별 + pooled, AUROC + BEDROC, 그리고 두 가지 평가셋을 같이 낸다.

- **held-out-positives** — valid split positive vs 전체 hard negative (기존 보고 방식)
- **leak-free** — 양쪽 클래스 모두 valid CID로 제한. 기존 방식은 negative의 90%가 학습에 쓰인 화합물이었고, 그 화합물들은 자기 짝이 아닌 포켓에서 점수가 내려가도록 학습되므로 AUROC가 부풀려진다 (실측: 학습에 쓰인 negative 평균 0.0523 vs 안 쓰인 negative 0.0727).

`score_panels.sh` / `score_bpa_panel.sh` 신규: 세 체크포인트를 **동일 설정**(`--max-pocket-atoms 450`, PPARγ 포켓이 422원자라 기본값 256이면 잘림)으로 재채점. `eval_{base,v1,v2}/`.

## 12단계 — 진짜 held-out 검증셋 3종

지금까지 유일한 검증이 BPA였는데, BPA는 **답을 이미 아는 유일한 화합물**이다. 포켓 7개 중 3개(ERα 3UU7, ERRγ 2E2R, PPARγ 9F7W)가 BPA가 실제로 박혀 있는 결정구조이고, 포즈 검증도 그 3개에서만 가능했다. 게다가 BPA 1위가 우리 쪽 버그에 따라 ERα ↔ ERRγ로 왔다 갔다 했는데 **두 답 다 문헌으로 옹호 가능**해서, 출력이 발견인지 우연인지 구분이 안 된다.

**(1) 비스페놀 holdout** (`build_bisphenol_holdout.py` → `bisphenol_holdout.csv`)

11개 비스페놀은 `build_pairs.py`가 처음부터 학습에서 제외했지만 raw assay JSON에는 결과가 남아 있다. 5개 리셉터에서 **51쌍 측정치, 39쌍 사용 가능**(Inconclusive 제외). valid split보다 깨끗하다 — 어떤 형태로도 학습에 안 들어갔다.

| | pooled | ERα | AR | PPARγ | PR |
|---|---|---|---|---|---|
| pretrained | 0.839 | 1.000 | 0.833 | 1.000 | 1.000 |
| v1 | 0.747 | 1.000 | 0.722 | 1.000 | 1.000 |
| v2 | 0.852 | 1.000 | **0.667** | 1.000 | 1.000 |

⚠️ ERα·PPARγ·PR이 세 체크포인트 **전부 1.000**이다. negative가 각각 2·1·1개뿐이라 만점이 너무 쉽고, **체크포인트를 구분하지 못한다.** 여유가 있는 유일한 리셉터 AR에서는 v2가 제일 나쁘다(9단계 bootstrap과 방향 일치). pooled 0.85는 보고하면 안 된다 — 클래스 비율과 리셉터 오프셋이 큰 평가셋과 완전히 달라서다.

정확검정 + 분자량 대조(포켓이 안 들어간 자명한 랭커)를 붙이면 진짜 신호는 두 개뿐이다:

| 리셉터 | n | 모델 | p | 분자량만 | p |
|---|---|---|---|---|---|
| **ERα** | 6+/2− | 1.000 | **0.036** | 0.750 | 0.214 |
| AR | 3+/6− | 0.667 | 0.274 | 0.167 | 0.952 |
| PPARγ | 2+/1− | 1.000 | 0.333 | 0.000 | 1.000 |
| PR | 10+/1− | 1.000 | 0.091 | 0.500 | 0.545 |

PPARγ·PR의 1.000은 달성 가능한 최소 p가 각각 0.333, 0.091이라 의미 없다. 별도로 **THRβ 특이성 검사**: Tox21에서 전부 Inactive인 비스페놀 8개 중 5개가 THRβ 점수를 나머지 6개 리셉터 전부보다 낮게 받았다(우연이면 1/5, P(X≥5)=0.010).

**(2) BPA 닮은꼴 (미구축, 재료 확인 완료)**

현 검증셋의 약점은 11개가 전부 사촌이고 대부분 active라 "닮았는데 안 붙는" 화합물이 없다는 것. Tox21은 같은 ~8,099개 라이브러리를 모든 리셉터에 반복 스크리닝하므로 그런 화합물이 **실측 음성으로** 존재한다. 지금 SMILES가 있는 1,555개(그마저 "어딘가 active" 편향)만 훑어도 BPA 닮은꼴 81개가 나오고:

| 리셉터 | Active | Inactive |
|---|---|---|
| ERα | 38 | 21 |
| AR | 38 | 33 |
| PPARγ | 20 | 14 |

현 검증셋(ERα 6+/2−)의 6배다. 예: CID 11742(Tanimoto 0.80) Active, CID 76013(0.45) **Inactive**, CID 7381(0.40) **Inactive**.

**함정**: 81개 중 **70개가 이미 학습에 들어가 있다**(미사용 10, valid 4). 비스페놀 11개를 뺐던 것과 같은 방식으로 제외 후 재학습해야 쓸 수 있다.

**(3) Glide 대조** (`build_glide_panel.py`, `glide_vs_drugclip.py`)

`scores/`에 연구실의 Schrödinger Glide SP 출력이 있었다(9/13 `flexible_five_v1`, 32 화합물 × 6 리셉터, `r_i_glide_gscore`). 물리 기반에 리셉터도 따로 준비된 **독립적인 자**라, 같은 쌍에서 Tox21 라벨과 맞춰보면 ERα 실패가 어느 쪽 문제인지 가를 수 있다.

| 리셉터 | n | Glide | DrugCLIP v2 | DrugCLIP pretrained |
|---|---|---|---|---|
| ERα | 9+/5− | 0.911 | 0.911 | 0.911 |
| AR | 6+/10− | 0.717 | 0.667 | 0.717 |

ERα 삼중 일치는 **진짜 우연**이다 — 순위는 셋 다 다른데 불일치 쌍 수만 똑같이 4/45로 떨어졌다(`Glide AAAAAAA.A..A..` vs `DC AAAAAAAA....A.`).

⚠️ **이걸로는 진단이 안 된다.** 32개 CID가 사실상 비스페놀 패널 + 유사체라, DrugCLIP이 이미 1.000을 내던 쉬운 구간이다. 두 자가 다 잘하는 건 판별이 아니라 문제가 쉬운 것. 진단하려면 **어려운 구간**(Tox21 ERα 743078의 ~8,099 화합물)에 Glide가 필요하다 — `completion.json` 기준 32개에 173초였으니 8,000개면 단일코어 ~12시간, 병렬로는 훨씬 짧다.

부수 소득: 비스페놀에 한해 물리 기반과 임베딩 기반이 **독립적으로 같은 결론**(0.911 vs 0.911)에 도달한다. 플래그십 사례가 방법론 2개로 교차 검증된 셈.

## 13단계 — 점수는 패널에 안 흔들린다. 흔들리는 건 지표다

"입력 범위에 따라 값이 달라지는 게 말이 안 된다"는 지적을 검증했다. 같은 체크포인트로 **3개 패널**과 **11개 패널**을 따로 채점한 BPA 점수는 7개 리셉터 전부 **소수점 4자리까지 동일**하다. 구조상 당연하다 — `score = cos(pocket_emb, mol_emb)`이고 두 임베딩이 독립적으로 계산된다. "리간드 주면 리셉터 주르륵"은 `retrieve_receptors.py`로 이미 된다.

실제로 움직인 것들의 정체:

| 움직인 것 | 원인 | 정당한가 |
|---|---|---|
| 패널 크기 | — | 영향 0 |
| PPARγ 0.0148 → 0.5381 | 포켓 추출 버그(8단계) | ❌ 우리 입력이 틀렸던 것 |
| ERα 0.844 → 0.6216 | 체크포인트 교체 | ✅ 다른 모델이니 당연 |
| **AUROC 0.409 ↔ 1.000** | **비교셋 교체** | ⚠️ 여기가 문제 |

**근본 원인: 점수에 절대적 의미가 없다.** 0.6615는 단위가 없고 "이 위면 붙는다"는 기준선이 없다. `in_batch_softmax`는 순수하게 상대적인 목적함수라 — loss가 묻는 건 "정답 쌍이 배치 안 다른 쌍들보다 위인가"뿐 — 값 자체가 뭔가를 의미하도록 만드는 압력이 없다. 그래서 "잘 붙는다"를 말하려면 결국 뭔가와 비교해야 하고, 비교셋에 따라 지표가 흔들린다.

리셉터마다 점수 스케일이 다른 것도 같은 뿌리다. BPA의 ERα 0.6615와 THRβ 0.2943을 나란히 놓는 건 두 포켓이 같은 자로 재어졌다는 가정인데, 사실이 아니고 그게 pooled AUROC를 부풀린 리셉터 오프셋이다.

지금 측정 라벨로 최적 컷을 잡아봐도 쓸모가 없다:

| 리셉터 | AUROC | 기저율 | 컷 | 정밀도 | 재현율 | lift |
|---|---|---|---|---|---|---|
| ERα | 0.529 | 7.2% | 0.268 | 14.5% | 18.6% | 2.0x |
| AR | 0.621 | 11.4% | 0.373 | 55.6% | 25.0% | 4.9x |
| PPARγ | 0.616 | 3.8% | 0.336 | 17.6% | 18.8% | 4.6x |
| PR | 0.606 | 26.6% | 0.068 | 35.3% | 74.4% | 1.3x |

(컷을 평가한 데이터에서 직접 골랐으므로 낙관 편향이 있다 — 제대로 held-out으로 잡으면 더 나쁘다.) **컷은 그 아래 깔린 순서만큼만 좋다. 보정으로는 순서를 못 고친다.**

## 데이터 가용성 확인 — 포켓이 5개인 건 데이터가 없어서가 아니다

포켓 구조는 7개 만들어져 있는데(`pocket_bpa_panel.lmdb`) 학습에 5개만 쓰인 건 **assay 라벨을 5개 리셉터 것만 당겨왔기** 때문이다. PubChem에 직접 조회한 결과, Tox21 assay 273개 중 핵수용체 타깃이면서 화합물 3,000개 이상인 것:

| 리셉터 | assay 수 | 화합물 수 | 현재 사용 |
|---|---|---|---|
| ERα | 11 | 7,671~8,099 | 1개 (743078, antagonist) |
| AR | 11 | 7,671~8,099 | 2개 |
| VDR | 4 | 7,329 | ❌ |
| PR | 4 | 7,671 | 1개 |
| **ERβ** | **4** | **7,671** | ❌ **포켓 있는데 안 씀** |
| PPARγ | 4 | 7,329~8,099 | 1개 |
| RXRα | 2 | 7,671 | ❌ |
| AhR | 2 | 8,099 | ❌ |
| PXR | 1 | 7,671 | ❌ |

주의: **AhR은 핵수용체가 아니다**(bHLH-PAS). "같은 패밀리라 서로 hard negative"라는 논리가 안 맞으니 별도 판단 필요. **GR(NR3C1)은 Tox21에 3,000개 넘는 assay가 없어** ChEMBL을 써야 한다.

**진짜로 데이터가 없는 건 ERRγ 하나.** PubChem 전체 assay가 112개뿐이고 Tox21에 대규모가 없다(DESIGN.md의 1,366개짜리 AID 1224820이 사실상 전부). 하필 문헌상 BPA가 가장 강하게 붙는다는 리셉터(Kd=5.5nM)가 학습 데이터가 제일 없다.

**덤**: ERα **agonist** assay가 8,099 화합물 규모로 3개 있다(743075, 743077, 743079). 현재 ERα positive는 전부 **antagonist** assay(743078)인데 포켓은 BPA-bound **agonist** 결정구조(3UU7)라 라벨과 구조가 안 맞는다. 이게 ERα가 세 체크포인트 내내 0.39~0.42에 고정된 원인일 수 있고, 확인할 재료가 이미 공개되어 있다.

## 알려진 한계 / 다음에 할 일

### 지금 막혀 있는 곳

**ERα가 세 체크포인트 내내 leak-free AUROC 0.39~0.42(랜덤 이하)로 고정되어 있다.** 파인튜닝으로 안 움직인다는 건 학습 문제가 아니라 입력 문제라는 뜻이고, 가설이 두 개인데 아직 안 갈렸다:

1. **라벨↔구조 불일치** — positive가 antagonist assay(743078)인데 포켓은 agonist 결정구조(3UU7)
2. **포켓 과적합** — 3UU7이 BPA가 박힌 구조라 비스페놀 모양으로 깎였고, 그래서 비스페놀은 잘 고르고(1.000, p=0.036) 일반 화합물은 못 고른다(0.409)

두 관측이 정확히 이 패턴이라 현 데이터로는 구분이 안 된다. 가르는 방법:

- **ERα 포켓 교체** (비스페놀 안 든 다른 ERα 결정구조로) — 재학습 없이 채점만, 가장 쌈. 가설 2 검증
- **ERα agonist assay(743075/743077/743079)로 교체 후 재학습** — 가설 1 검증
- **어려운 구간 Glide** (Tox21 743078 화합물 ~8,099개) — 독립적인 자로 판별. Glide도 낮으면 포켓/라벨 문제, Glide가 멀쩡하면 DrugCLIP 표현력 문제
